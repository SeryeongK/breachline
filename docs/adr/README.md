# 설계 기록 (ADR)

중요한 설계 결정마다 파일 하나. 파일명은 `0001-결정-제목.md`처럼 번호를 붙인다.

## 목록

| # | 제목 | 상태 | 영역 | 날짜 |
| --- | --- | --- | --- | --- |
| - | (아직 없음) | | | |

상태: 제안 · 확정 · 대체됨(→ 새 번호)
영역: 전체 · gateway · agent · simulator · attacker · console · labs · infra

## ADR을 쓰는 기준

아래 중 **하나라도** 해당하면 ADR로 쓴다.

- 되돌리기 어려운 결정 (예: 모노레포, DB 종류, 실습 모드 구조)
- 여러 모듈에 영향을 주는 결정 (예: 메시지 형식, 서명 방식)
- 대안을 진지하게 비교한 결정 (특히 깊이 포인트 ①~④)

해당하지 않는 작은 결정(변수 이름, 라이브러리 버전 등)은 커밋 메시지 본문이나 코드 주석에 남긴다.

## 운영 규칙

- 확정된 ADR은 내용을 고치지 않는다. 결정이 바뀌면 새 ADR을 쓰고, 옛 ADR 상태를 "대체됨(→ 새 번호)"으로 바꾼다
- ADR을 추가하거나 상태가 바뀌면 위 목록표를 갱신한다
- 수십 개를 넘어 찾기 어려워지면 영역별 폴더(`adr/gateway/` 등)로 나누는 것을 검토한다

## 양식

```markdown
# 0001. 제목

- 상태: 제안 / 확정 / 대체됨(0005)
- 날짜: YYYY-MM-DD

## 배경
무엇을 정해야 했고, 왜 지금인가

## 대안
| 대안 | 장점 | 단점 |
| --- | --- | --- |

## 결정
무엇을 골랐는가

## 이유
왜 골랐는가

## 한계
이 결정으로 감수하는 것, 나중에 다시 볼 조건
```
